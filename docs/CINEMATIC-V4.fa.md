# ارکام — تحویل بازطراحی سینمایی V4

## نتیجه و دامنه

این نسخه، کد قابل اجرای پروژه موجود را ارتقا می‌دهد؛ سایت روی VPS شما در این جلسه تغییر نکرده و چیزی به Git شما push نشده است. نام فارسی رابط و محتوای نمونه «ارکام» است؛ نشان رسمی و نام لاتین ARKHAM حفظ شده‌اند. حساب مدیر و اطلاعات سرور شما داخل بسته نیستند.

صفحه نخست هفت فصل دارد: ورود، داستان، مجموعه محصول، نمای نزدیک، بسته‌بندی، انتخاب آگاهانه و دعوت پایانی. یک Canvas مشترک در همه فصل‌ها باقی می‌ماند. جای شیشه، چرخش، دوربین، مسیر زنبور، رنگ زمینه و ظاهرشدن متن به پیشرفت واقعی اسکرول وابسته‌اند؛ هفت Canvas یا هفت تصویر ثابت جایگزین نشده‌اند. بعد از روایت، مجموعه، دسته‌بندی، مجله و FAQ در دسترس‌اند. لینک مستقیم فروشگاه و خروج از روایت هم وجود دارد.

## بررسی پروژه و نمونه نهلا

- پروژه اصلی: React 19/TypeScript/Vite، Three/R3F، Lenis و API سروری Django/PostgreSQL؛ سبد سروری، مجوزهای پنل و جریان سفارش قابل استفاده مجدد بودند. Hero قدیمی صحنه‌ای مستقل داشت و زبان بصری تیره/طلایی غالب بود.
- نمونه نهلا: صفحات index/about/products/product/contact/admin، CSS، فایل nahla-core.js و سرور Express بررسی شدند. نمونه از JSON فایل‌محور و مسیر fallback مرورگر/localStorage استفاده می‌کند؛ احراز هویت آن الگوی مناسب انتقال به این فروشگاه نیست.
- از نهلا فقط جهت بصری کرم، حس گیاهی و ریتم خلوت الهام گرفته شده است. کد احراز هویت، رمز پیش‌فرض، ساختار ذخیره سفارش، لوگو یا نام نهلا وارد پروژه نشده‌اند. Express یا localStorage جایگزین دیتابیس نشده است.
- تصاویر مرجع برای ترکیب‌بندی و حس نور/بسته‌بندی استفاده شدند، نه بازنشر لوگوی برندهای دیگر یا ادعای واقعی درباره کیفیت ارکام.

## جهت طراحی

کرم گرم `#FFF6E5` و عاجی `#FFFCF5`، طلایی عسلی `#D5A33C`، کهربایی `#B87519`، سبز گیاهی `#314A32` و جنگلی `#1C3024`؛ تایپ فارسی محلی Vazirmatn؛ خطوط گیاهی SVG اختصاصی، گل‌های سه‌بعدی، ذرات معلق و مدارهای ظریف طلایی. متن اصلی HTML و قابل انتخاب است، نه نوشته داخل تصویر. پالت روشن و تیره در گذارها با انتخاب خودکار رنگ متن هماهنگ می‌شود.

شیشه به‌صورت procedural ارتقا یافته است: بدنه lathe، لایه داخلی عسل، پوسته شیشه، پایه، درپوش چندحلقه‌ای و شیارها، برچسب اختصاصی سبز/طلایی با نشان رسمی و حکاکی گیاهی. زنبور چشم، شاخک، پا و بال‌های مجزا دارد؛ حرکت پرواز با اسکرول و شناوری آرام ترکیب شده است. این خروجی مدل سه‌بعدی برند است، نه اسکن دقیق محصول واقعی و نه شبیه‌سازی فیزیکی مایع.

## ادغام با فروشگاه

- محصول، تصویر، نام، قیمت جاری، وزن و موجودی از API فعلی دریافت می‌شوند. هیچ قیمت یا شناسه کالای ثابتی در صحنه قرار نگرفته است.
- در فصل مجموعه، اسکرول انتخاب محصول را تغییر می‌دهد؛ انتخاب دستی با تصویر بندانگشتی و افزودن به سبد هم کار می‌کند.
- نمایش بسته هدیه به وجود محصول مرتبط در کاتالوگ وابسته است؛ تصویر واقعی منتشرشده همان محصول کنار روایت دیده می‌شود. هندسه سه‌بعدی یک تصویرسازی عمومی است و تطبیق دقیق بسته فیزیکی را ادعا نمی‌کند.
- مسیرهای محصول، سبد، تسویه، حساب، سفارش، ورود، مجله، تماس، پیگیری، پنل اختصاصی و Django Admin باقی مانده‌اند.
- هیچ مشتری، نظر، سفارش پرداخت‌شده، آمار فروش یا گواهی ساختگی برای پرکردن صفحه ایجاد نشده است. داده‌های تست در دیتابیس موقت جدا ساخته و حذف می‌شوند.

## ویرایش محتوا در پنل

ورود با همان حساب مدیر خودتان در `/login`؛ پنل روزمره `/manage`، پنل داخلی `/django-admin/`. مدیر پیش‌فرض یا رمز ثابت ساخته نشده است.

در «محتوای سایت»، رکوردهای منتشرشده زیر خوانده می‌شوند:

| کلید | کاربرد |
|---|---|
| `hero` | title و body فصل اول |
| `story` | داستان کامل و خلاصه فصل دوم |
| `benefits` | title و `settings.items` با title/body برای سه مورد |
| `faq` | `settings.sections` با title/body؛ چهار مورد در خانه |
| `contact` | متن تماس؛ `settings.footer_text` برای خلاصه مستقل فوتر |
| `experience` | تنظیمات اختیاری روایت جدید؛ در نبود آن متن پیش‌فرض استفاده می‌شود |

برای سفارشی‌سازی روایت، رکوردی با key برابر `experience` و published فعال بسازید. نمونه فیلد JSON settings:

```json
{
  "storyTitle": "هر طعم،\nآغاز یک روایت.",
  "storyBody": "متن کوتاه و تأییدشده داستان برند شما.",
  "detailTitle": "زیبایی،\nدر جزئیات است.",
  "detailBody": "توضیح تأییدشده درباره طراحی بسته‌بندی.",
  "packagingTitle": "یک هدیه،\nچند لحظه شیرین.",
  "finalTitle": "لحظه بعدی را\nشیرین‌تر انتخاب کنید.",
  "finalBody": "دعوت کوتاه شما برای دیدن مجموعه."
}
```

عنوان‌ها را کوتاه و متن هر فصل را حدود ۱۲۰ تا ۱۸۰ کاراکتر نگه دارید. متن بسیار بلندِ اختصاصی باید در موبایل دوباره بررسی شود. لوگوی `logo-dark` در دارایی‌های برند همچنان اولویت دارد؛ فایل نشان همراه پروژه fallback است. تصاویر مقاله با کلید `article-` به‌علاوه slug مقاله و تصویر داستان با `story-image` مدیریت می‌شوند.

## ارتقای امن سرور موجود شما

**صرفاً اجرای git fetch، کدی را که هنوز به مخزن شما نرسیده وارد نمی‌کند.** ابتدا محتوای این بسته را در مخزن خودتان ادغام، commit و push کنید یا با روش استقرار معمولتان به سرور انتقال دهید. `.env`، دیتابیس و media سرور را با فایل محلی جایگزین نکنید. از ZIP فقط کد/دارایی‌های همراه را منتقل کنید؛ پوشه داخلی ZIP به نام `arkham` است.

### ۱. بکاپ قبل از تعویض کد

از مسیر فعلی پروژه، با سرویس‌های فعلیِ روشن:

```bash
cd /home/ubuntu/arkham
# هر دستور باید موفق شود؛ در صورت خطا، مرحله بعد را اجرا نکنید.
backup="../arkham-backup-$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -m 700 "$backup"
cp -p .env "$backup/.env"
chmod 600 "$backup/.env"
docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > "$backup/database.dump"
docker compose exec -T backend tar -C /app/backend -czf - media > "$backup/media.tar.gz"
test -s "$backup/database.dump" && test -s "$backup/media.tar.gz"
```

بکاپ، به‌خصوص `.env` و دیتابیس، خصوصی است؛ آن را در Git یا چت قرار ندهید. بکاپ‌گرفتن معادل تأیید restore نیست؛ بازیابی باید جداگانه روی staging آزموده شود.

### ۲. کد جدید و سرویس‌ها

بعد از رسیدن همین نسخه به مخزن و نگهداری تغییرات محلی لازم، کد را با روش معمول به‌روزرسانی کنید. سپس:

```bash
docker compose config --quiet
docker compose build backend frontend
docker compose run --rm permissions
docker compose up -d
docker compose ps -a
docker compose logs --tail=80 permissions migrate backend frontend
```

سرویس یک‌بارمصرف `permissions` فقط volumeهای media و static را برای UID/GID برنامه `10001:10001` آماده می‌کند؛ مجوز پوشه 755 و فایل 644 است. ریشه دیتابیس را mount یا chown نمی‌کند. پس از موفقیت، migrate و collectstatic اجرا و سپس backend بالا می‌آید. روی مدیای بسیار بزرگ، chown اولیه ممکن است زمان ببرد. سرویس وب همچنان non-root است.

اگر از `git reset --hard origin/main` استفاده می‌کنید، ابتدا مطمئن شوید تغییرات ضروریِ کد در مخزن ذخیره شده‌اند؛ این فرمان تغییرات tracked محلی را دور می‌ریزد. برای این ارتقا **`docker compose down -v` اجرا نکنید**؛ این کار می‌تواند volumeهای اطلاعات شما را حذف کند.

### ۳. تغییر نام محتوای ذخیره‌شده، بدون seed دوباره

کد رابط فوراً «ارکام» را نمایش می‌دهد؛ عنوان‌های قبلی در دیتابیس با دستور اختیاری زیر اصلاح می‌شوند:

```bash
# ابتدا فقط پیش‌نمایش؛ چیزی ذخیره نمی‌شود:
docker compose exec backend python manage.py upgrade_brand
# سپس، پس از بررسی تعداد رکوردها:
docker compose exec backend python manage.py upgrade_brand --apply
```

دستور فقط صورت‌های قبلی نام فارسی را در فیلدهای متنی کاتالوگ/مقاله/محتوا/alt تغییر می‌دهد؛ slug، URL، قیمت، موجودی، کاربران، رمزها، آدرس‌ها و سفارش‌ها دست‌نخورده می‌مانند. این کار جایگزین seed نیست و محصول تازه ایجاد نمی‌کند.

برای جایگزینی فقط عکس‌های تحریریه دمو قدیمی با سه تصویر AI جدید و بزرگ‌تر:

```bash
docker compose exec backend python manage.py upgrade_brand --refresh-demo-images
# بررسی پیش‌نمایش، سپس:
docker compose exec backend python manage.py upgrade_brand --apply --refresh-demo-images
```

فقط چهار کلید شناخته‌شده با نام فایل `demo-...` جایگزین می‌شوند؛ عکس آپلودی واقعی مالک تغییر نمی‌کند و فایل قدیمی هم از دیسک حذف نمی‌شود. اجرای دوباره تکراری و مخرب نیست. عکس محصولات موجود عمداً بازنویسی نمی‌شود.

چون شما قبلاً پیام `Demo ready` و `Superuser created successfully` گرفته‌اید، برای این ارتقا نیازی به seed یا ساخت دوباره مدیر ندارید. اگر داده در سایت پیدا نشد، نخست اتصال همان backend به همان volume/دیتابیس، فعال‌بودن محصولات و پاسخ `/api/v1/products/` را بررسی کنید؛ `DEBUG=1` را برای عیب‌یابی روی سایت عمومی فعال نکنید.

### ۴. کنترل پس از ارتقا

- `/api/v1/health/` و صفحات فروشگاه را بررسی کنید؛ کش مرورگر را با hard refresh تازه کنید.
- با همان مدیر قبلی وارد `/manage` شوید؛ قیمت/موجودی و عکس‌ها را بررسی کنید.
- در حالت دمو فقط پرداخت Mock را امتحان کنید. تنظیمات پرداخت واقعی با این ارتقا فعال نمی‌شوند.
- هیچ رمز مدیریتی را در فرمان عمومی، URL یا گزارش خطا منتشر نکنید.

## عملکرد، دسترس‌پذیری و محدودیت واقعی

- یک Canvas lazy، DPR محدود، ذرات کمتر و سایه سبک‌تر/خاموش در کیفیت پایین، PMREM محلی، بدون CDN/HDRI شبکه‌ای و بدون کتابخانه اضافه؛ منابع و listenerها هنگام خروج پاک می‌شوند و رندر خارج دید متوقف می‌شود.
- reduced-motion و ارتفاع کمتر از ۶۲۰px: روایت خوانا در جریان عادی صفحه و عکس دوبعدی، بدون Canvas. از دست رفتن WebGL نیز fallback دارد؛ خرید حذف نمی‌شود.
- فصل غیرفعال inert است؛ دکمه‌های فصل با کیبورد کار می‌کنند. هدف‌های لمسی فصل و محصول حداقل ۴۴px هستند. اسکرول لمس native باقی می‌ماند. چرخش دستگاه و viewportهای کوتاه حالت ساده می‌گیرند.
- هندسه procedural است، نه GLB فوتورئال اختصاصی یا شبیه‌سازی جریان/قطره عسل. Bloom/DOF/motion blur سنگین عمداً اضافه نشده‌اند. زنبور قابل مشاهده و پیوسته است، اما رفتار جانورشناسی یا نشستن فیزیکی واقعی شبیه‌سازی نشده است.
- کارایی روی گوشی فیزیکی، Safari/iOS واقعی، Core Web Vitals و Lighthouse اندازه‌گیری نشده‌اند. نتایج Chromium نرم‌افزاری و viewport emulation را نرخ فریم موبایل واقعی ندانید.
- Docker در این محیط اجرا نشده است؛ بررسی ساختاری Compose جای build/run واقعی Docker روی staging را نمی‌گیرد. این بند درخواست هنوز به دسترسی استقرار نیاز دارد.
- تمام محدودیت‌های تجاری/مالی/درگاه/حقوقی در STATUS.fa.md همچنان معتبرند. این تغییر طراحی، مجوز شروع فروش واقعی نیست.

## فایل‌ها و وابستگی‌ها

جدید: `frontend/src/experience/{ExperienceShell.tsx,BotanicalLayer.tsx,timeline.ts,experience.css}`، تست timeline، فرمان و تست `upgrade_brand`، سه WebP با وضوح واقعی ۱۲۶۴×۸۴۸ در `backend/demo_assets/v4/`، تست مرورگری V4 و این راهنما.

بازنویسی/ویرایش اصلی: `Scene.tsx`، اتصال Home و نام برند در `main.tsx`، متن‌های backend/templates/store و metadata، انتخاب تصاویر در seed_demo و `docker-compose.yml`. فایل dist دوباره build شده است. فهرست کامل فایل‌های بسته و SHA-256 هر فایل در MANIFEST.sha256 موجود است. وابستگی جدیدی نصب/اضافه نشده؛ React/R3F/Three/Lenis موجود استفاده می‌شوند. منطق پرداخت و موجودی برای بازطراحی تغییر نکرده است.

گزارش‌های همین نسخه با `v4-` شروع می‌شوند؛ گزارش‌های V3 و بدون پیشوند، تاریخی‌اند. معیار پذیرش و موارد نیازمند دسترسی در `CINEMATIC-ACCEPTANCE.fa.md` آمده‌اند.
