# اجرای دمو و ورود به مدیریت

## ساده‌ترین راه روی Linux/macOS

پیش‌نیازها: Python 3.13، Node.js 24، npm و ترمینال. فرمان‌ها را در پوشه `arkham` فایل ZIP اجرا کنید. اینترنت برای نصب اولیه وابستگی‌ها لازم است. این دستور از SQLite جداگانه محلی استفاده می‌کند؛ PostgreSQL و Docker برای دیدن دمو لازم نیستند.

```bash
chmod +x scripts/*.sh
./scripts/run-demo.sh
```

این اسکریپت محیط Python، وابستگی‌ها و build فرانت‌اند را آماده می‌کند، دیتابیس محلی را می‌سازد و محتوای دمو را وارد می‌کند. سپس سایت در `http://127.0.0.1:8000` بالا می‌آید. ترمینال را باز نگه دارید. دیتابیس در `backend/dev.sqlite3` است و با PostgreSQL استقرار تجاری یکی نیست. کلید توسعه در `.demo-secret` محلی ساخته می‌شود؛ آن را منتشر نکنید.

در **ترمینال دوم**، داخل همان پوشه:

```bash
./scripts/create-demo-admin.sh
```

نام کاربری، ایمیل و رمز قوی خودتان را در ترمینال وارد کنید؛ هنگام تایپ رمز چیزی نمایش داده نمی‌شود. حساب یا رمز ثابت پیش‌فرض وجود ندارد. رمز را در چت، فایل عمومی یا مخزن کد نگذارید.

سپس:

1. `http://127.0.0.1:8000/login` را باز کنید و با همان حساب وارد شوید.
2. به `http://127.0.0.1:8000/manage` بروید؛ لینک «مدیریت» برای حساب staff هم نمایش داده می‌شود.
3. پنل داخلی Django برای نقش‌ها و امکانات داخلی: `http://127.0.0.1:8000/django-admin/`.

اگر پورت اشغال است، مثلاً `DEMO_PORT=8010 ./scripts/run-demo.sh` را اجرا و آدرس‌های بالا را با پورت ۸۰۱۰ باز کنید. توقف سرور با Ctrl+C است. داده‌ها با راه‌اندازی مجدد حفظ می‌شوند.

## نصب موجود PostgreSQL / Docker

اسکریپت بالا عمداً دیتابیس مستقل خودش را دارد. حسابی که در PostgreSQL ساخته‌اید در SQLite وجود ندارد و برعکس. برای نصب PostgreSQL موجود، در همان محیط و دیتابیسی که سرور را اجرا می‌کنید:

```bash
python manage.py createsuperuser
```

برای کانتینرهای نصب موجود، پس از پیکربندی و بالا آمدن سرویس‌ها:

```bash
docker compose exec backend python manage.py createsuperuser
```

پنل اختصاصی `/manage` و پنل داخلی `/django-admin/` هستند. تنظیم HTTPS/دامنه/دیتابیس Production در DEPLOYMENT.fa.md است؛ Docker و استقرار واقعی این نسخه در این محیط اجرا نشده‌اند. DEBUG و SQLite را برای انتشار عمومی فعال نگذارید.

## داده‌های موجود در دمو

- ۶ محصول: آویشن، اقاقیا، کوهستان، عسل و گردو، بهارنارنج، جعبه هدیه.
- ۱۱ گونه وزنی، ۳ دسته، ۳ مقاله کامل، داستان برند، مزیت‌های نمایشی، FAQ بازشونده، ارسال، حریم خصوصی، شرایط و تماس نمونه.
- عکس‌های AI به‌همراه نشان واقعی مالک؛ نه عکس یا گواه محصول واقعی. تصاویر مجله و بنر هم تولیدشده‌اند.
- دو روش ارسال نمونه و کوپن `DEMO10` با تخفیف ۱۰٪، حداقل ۲۰۰هزار تومان و حداکثر ۵ بار برای هر حساب (اعتبار ۹۰ روز از اجرای seed).
- هیچ مشتری، مدیر، نظر مثبت یا سفارش پرداخت‌شده جعلی ساخته نمی‌شود. علاقه‌مندی/حساب/سفارش با تعامل خودتان پر می‌شوند.
- خبرنامه و فرم تماس داده را ذخیره می‌کنند؛ سرویس ارسال ایمیل متصل نیست. از اطلاعات ساختگی برای آزمایش استفاده کنید.

دستور ورود دوباره محتوا در محیط تنظیم‌شده دمو:

```bash
python backend/manage.py seed_demo --confirm-demo
```

این فرمان فقط با `DEBUG=1`، `DEMO_MODE=1` و `PAYMENT_PROVIDER=mock` مجاز است. رکوردهای دمو را دوباره ایجاد نمی‌کند، موجودی مصرف‌شده را reset نمی‌کند و متن واقعی موجود را بازنویسی نمی‌کند. شناسه‌های محصول/مقاله با `demo-` و SKUها با `DEMO-` شروع می‌شوند. پرداخت واقعی برای سفارش حاوی SKU دمو در سرور مسدود شده است.

## حرکت و فرم‌ها

اسکرول نرم با Lenis 1.3.17، نمایان‌شدن یک‌باره کارت‌ها، حرکت متناوب چپ/راست و پارالاکس عکس‌ها اضافه شده است. این پیاده‌سازی حس اسکرول سینمایی/لوکوموتیو دارد؛ از پکیج Locomotive Scroll استفاده نمی‌کند. اسکرول لمسی native حفظ می‌شود. روی فرم‌های حساس مانند تسویه، ورود، حساب و مدیریت، اسکرول نرم و reveal تزئینی اجرا نمی‌شوند. با `prefers-reduced-motion` حرکت تزئینی غیرفعال می‌شود.

کنترل‌ها native هستند: انتخاب، چک‌باکس، ورودی فایل، حالت فوکوس و خطا، hover و تم تیره خبرنامه اصلاح شده‌اند. هیچ فرم یا فیلد صرفاً نمایشی جایگزین عملکرد اصلی نشده است.

## پیش از فروش واقعی

از دیتابیس پاک Production و اطلاعات واقعی استفاده کنید. تصاویر AI، متن‌ها و سیاست‌های نمونه را جایگزین کنید. فایل‌ها و flagهای دمو را منتشر نکنید؛ DEBUG و DEMO_MODE باید خاموش و پرداخت واقعی فقط پس از آزمون staging فعال شود. محدودیت‌های مالی و استقرار در STATUS.fa.md پابرجاست.
